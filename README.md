# Naming convention
If you need to do somthing that isnt coverd by this naming convention message me and ill add it :)
## github (naming convention ref) {https://www.conventionalcommits.org/en/v1.0.0/}
### commits
The summary of a commit should be structured as follows

{type} [scope(optinal)]: {description}

For example "art: added new house"

- exmaples of types 
    - feat - adaddition of a gameplay feature
    - Art - addition of a peice of artwork
    - Generic - updating a file e.g ReadMe.md or a game scene
    - fix - fixing an issue (this is added to an exisiting type e.g Art|Fix)

For the description describe all the changes you made

E.g updated house moddel  to ------

If there were multiple changes made it should look like 

Changes 
- change 1
- change 2
### branches
New brnaches should be named type/parent/name

e.g art/main/houses or art/houses/players-house

### merges

## files
Files added should follow the naming convention of Type_SubCatagory_Name
or Type_Name if no sub-catagory is named
e.g the mesh for the players house would be Mesh_House_PlayersHouse

File names should also follow the pascal case naming structure 
e.g the start of all words should be a capital, so Mesh_House_playersHouse not mesh_house_playershouse

### asset types 
- Mesh - a 3D moddels mesh
- Img - any image e.g a modles texture or a npc sprite
    - Tex - the texture for a 3d model
    - Sprite - a 2D sprite
- Mat - a material
- scripts - script names need to follow the pascal case
- Prf - Any prefab 
- Audio - any peice of audio 
    - SFX - any audio that is classed as an SFX
    - Music - any audio that is classed as music
- Sceen -any unity scenes
    - Gameplay - a scene deigned for gameplay  
    - menu - a scene that is used as a menu
